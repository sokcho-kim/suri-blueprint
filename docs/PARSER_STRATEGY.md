# 파서 전략 문서

## 개요

HIRA 전자자료 분류집(ebook)은 책자형 PDF로, 문서마다 레이아웃이 상이하다.
범용 PDF 파서 하나로 모든 문서를 처리할 수 없으며, 문서 유형별 파싱 전략이 필요하다.

## 파서 비교 결과 (2026-04-23)

### 테스트 대상

`KDRG V4.7 분류집(부록).pdf` — 진단코드/시술코드 색인 (4단 다단 컬럼, 776p)

### Approach A: opendataloader-pdf JSON 후처리

- **방식**: opendataloader-pdf로 JSON(bounding box 포함) 추출 → 코드 패턴 매칭
- **결과**: GT 13건 중 **0건 hit** (Recall 0.000)
- **원인**: 4단 컬럼이 하나의 paragraph로 합쳐져 코드 간 경계 소실
- **결론**: 다단 컬럼 분류집에는 부적합

### Approach B: PyMuPDF span 좌표 기반 파싱

- **방식**: PyMuPDF(fitz)로 span 단위 텍스트+좌표 추출 → X좌표 기반 컬럼 분리
- **결과**: GT 13건 중 **13건 hit** (Recall 1.000, Precision 0.433)
- **원인**: span 단위 좌표가 정확해서 컬럼 분리가 가능
- **결론**: 다단 컬럼에 적합. Precision 개선 여지 있음 (인접 컬럼 오탐)

### 적응형 파서 (최종 채택)

- **방식**: 매 페이지 헤더(`진단코드 MDC ADRG`)를 자동 감지 → 동적 컬럼 경계 계산
- **결과**: 부록 110,684건 추출, Recall 100%
- **한계**: 본편 등 다른 레이아웃 문서는 별도 전략 필요

### 기타 검토한 도구

| 도구 | 적합성 | 비고 |
|------|--------|------|
| opendataloader-pdf | 부적합 (다단) | 단일 컬럼 문서에는 좋음 |
| dclaim-data-processor (팀장님) | PDF 파서 아님 | 파싱 이후 LLM 후처리 파이프라인 |
| document-processor (인턴) | PDF 미지원 | DOCX/HWP 전용, 테이블 파싱 우수 |

## Precision 개선 방향

현재 오탐 원인: 연속 행에서 인접 컬럼의 `last_mdc`가 리셋되지 않아 다른 코드의 매핑이 섞임.

개선 방안:
1. 새 진단코드 등장 시 해당 컬럼의 `last_mdc` 리셋
2. 더 넓은 GT로 검증 (13건은 너무 적음)
3. 원본 PDF 육안 대조로 실제 오탐/정탐 판별
